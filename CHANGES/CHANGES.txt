1. GEMINI SDK MIGRATION (google-generativeai -> google.genai)
------------------------------------------------------------------------------
The deprecated `google.generativeai` SDK was replaced by the modern
`google.genai` package (version 2.14.0 installed).

Files changed:
  - backend/requirements.txt
  - requirements.txt
  - requirements-updated.txt
    Added: google-genai, langchain-chroma
    Removed: google-generativeai

  - backend/app/embeddings.py
    `from langchain_community.vectorstores import Chroma`
    changed to `from langchain_chroma import Chroma`.

Key SDK findings (from direct API probes):
  - models.list() works and lists models/gemini-3.6-flash,
    models/gemini-3.5-flash, models/gemini-2.5-flash, models/gemini-2.5-pro.
  - gemini-2.5-flash rejects generation with 404 "no longer available to new
    users".
  - gemini-3.6-flash is free-tier quota limited (20 requests/day/model).
  - gemini-3.5-flash / 3.6-flash / 2.5-pro are THINKING models: response.text
    returns None (even with ThinkingConfig(include_thoughts=False)); the text
    lives in response.candidates[0].content.parts. Handled by _extract_text.
  - IMPORTANT BUG FOUND & FIXED: generate_content() in google-genai 2.14.0
    does NOT accept a `timeout=` keyword argument - it raises TypeError
    instantly. Because the error string contains the word "timeout", the old
    classifier mislabelled it as LLMTimeoutError and retried every model with
    a 2s/4s backoff on every question (~26s wasted per question). Fixed by:
      * Setting the timeout at client level via
        genai_types.HttpOptions(timeout=..., retryOptions=
        genai_types.HttpRetryOptions(attempts=1)).
      * Removing the unsupported timeout kwarg from generate_content().
      * Tightening _classify_error so only real timeout phrases
        ("deadline exceeded", "timed out", "read timeout", ...) and HTTP
        408/504/529 map to LLMTimeoutError.

2. backend/app/llm.py - REWRITTEN
------------------------------------------------------------------------------
- Uses genai.Client + genai_types (google.genai).
- LLMStatus constants: llm, fallback, quota, timeout, generation_error,
  api_error, empty.
- Typed errors: RetrievalError, LLMGenerationError, APIQuotaError,
  LLMTimeoutError, APIAccessError(unavailable flag).
- Model discovery via models.list() filtered on the generateContent action;
  falls back to config.PREFERRED_MODELS. Models that 404 are removed from the
  working set lazily.
- _generate_once: per-attempt retry with exponential backoff driven by config
  (LLM_MAX_RETRIES, LLM_RETRY_DELAY, LLM_BACKOFF_FACTOR).
- _quota_exhausted flag caches quota failures so a quota-limited day does not
  hammer the API on every question.
- CIRCUIT BREAKER (added when the API network was found unreachable): after a
  full failure sweep across all models, _cooldown_until = now +
  LLM_COOLDOWN_SECONDS. During cooldown, generate() returns the fallback
  immediately with the last status. Only one question per window pays the
  slow sweep cost.
- _classify_error maps HTTP codes and message substrings to typed errors.
- _extract_text handles thinking models by reading candidates[0].content.parts.
- Deterministic _fallback_generate using conflict.extract_claims,
  focus_attributes and format_conflict_notice (single/set/text semantics per
  ATTRIBUTE_TAXONOMY). It never performs arithmetic the source does not state
  and never dumps raw chunk text.
- generate() returns a (text, status) tuple.

3. backend/app/retriever.py - REWRITTEN
------------------------------------------------------------------------------
- Programme detection (_detect_program) and query keyword detection
  (_detect_query_keywords) driven by config.ATTRIBUTE_KEYWORDS.
- _has_value_near_keyword and _score_chunk produce a bounded relevance score:
  keyword boost (capped by KEYWORD_BOOST_MAX), value-proximity bonus (capped
  by VALUE_PROXIMITY_MAX), source-authority bonus (config.SOURCE_AUTHORITY_TIERS)
  and a global SCORE_CAP (<= 1.0).
- Candidate search uses a chromadb $or filter: query programme name, the
  "general" label, and discovered policy sources via $in; falls back to an
  unfiltered query if filtering returns nothing.
  IMPORTANT FINDING: chromadb 1.5.9 does NOT support {"source": {"$contains": ...}}
  (returns 0 results). Policy sources are therefore enumerated once via
  get(where={"program_name": ""}) and matched against
  config.GENERAL_POLICY_SOURCE_PATTERNS, then queried with $in. Cached in
  _policy_sources_cache.
- The full scored pool is kept in last_pool so conflict detection can inspect
  more than the final top-K.
- Results deduplicated (higher-scoring representative kept) and capped for
  diversity (max 2 chunks per source/page) before final TOP_K.
- Exposes last_query, last_program, last_keywords, last_pool.
- Stepwise score logging for diagnosis.

4. backend/app/rag_chain.py - REWRITTEN
------------------------------------------------------------------------------
- answer(): retrieve -> detect conflicts over retriever.last_pool (full
  diverse pool, not just top-K) -> build context -> generate.
- _build_context: each chunk gets a structured header (Source / Page / Chunk ID
  / Content Type / Document Type / Programme / Score) followed by content
  trimmed to CONTEXT_CHUNK_MAX_CHARS; total context bounded by
  CONTEXT_TOTAL_MAX_CHARS. A conflict notice is prepended when conflicts exist.
- Exposes last_status and last_conflicts.
- answer() returns (text, retrieved) - compatible with the CLI chatbot.

8. BUG FIXES
------------------------------------------------------------------------------
- google-genai timeout TypeError (see section 1) - biggest performance fix.
- retriever._policy_sources collided with a method name -> _policy_sources_cache.
- Conflict table rows like "| | Total Credits | 102 |" have the label in a
  later column -> parser now takes the first non-empty cell as the row label.

  (.150000 -> 0.15) -> now uses re.sub(r"[^\d.]", "", match).strip(".") with a
  clean != "." guard.
- source_authority matching is now case-insensitive.
- deduplicate_results now sorts score-descending first so the higher-scoring
  representative is always kept regardless of input order.
