1. SUMMARY OF CHANGES MADE
--------------------------------------------------------------------------------

A. TASK 1 - PDF INGESTION PIPELINE
   - Created a dedicated, modular PDF ingestion module (`backend/app/pdf_ingestion.py`).
   - Created dedicated storage directory `backend/knowledge_base/pdfs/`.
   - Processed `PPR_Online MBA.pdf` with page-by-page text & table extraction.
   - Added metadata to every chunk:
       * source          : "pdfs/PPR_Online MBA.pdf"
       * filename        : "PPR_Online MBA.pdf"
       * page            : Page number (1-indexed)
       * document_type   : "pdf"
       * content_type    : "text" | "table" | "image"
       * program_name    : "online_mba"
   - Added `add_documents()` to `EmbeddingStore` (`backend/app/embeddings.py`) to add PDF
     chunks incrementally into ChromaDB without overwriting existing website documents.
   - Created standalone CLI script `backend/ingest_pdfs.py` to separate ingestion/indexing
     from chatbot startup.

B. TASK 2 - TABLE-AWARE RETRIEVAL
   - Implemented PyMuPDF table detection and conversion into clean Markdown tables.
   - Configured `PDF_TABLE_CHUNK_SIZE = 1200` to preserve complete table rows and structure.
   - Marked table chunks with `content_type = "table"`.
   - Preserved exact table values for fees, semester credit breakdowns, and specializations
     without hallucination or manual invention.

C. TASK 3 - TEST RETRIEVAL SUITE
   - Built `backend/test_pdf_retrieval.py` covering all 7 target MBA questions.
   - Displays retrieved sources, page numbers, similarity scores, retrieved chunks,
     and final LLM answers with timing metrics.

D. TASK 4 - INCONSISTENCY HANDLING
   - Updated `backend/app/prompt.py` with an explicit Inconsistency Detection Rule.
   - Updated `backend/app/rag_chain.py` to pass page numbers and content types into context.
   - System automatically detects conflicting values (e.g. 102 vs 100 total credits in
     `PPR_Online MBA.pdf`), reports both figures, cites respective pages (Page 4 & 10 vs Page 12),
     and explicitly notes document inconsistency.

E. TASK 5 - MULTIMODAL PREPARATION
   - Architecture prepared with extensible `content_type` field ("text", "table", "image").
   - PDF ingestion decoupled into modular methods to allow adding a vision/multimodal
     retrieval layer in the future without rewriting existing code.

F. TASK 6 - CHATBOT STARTUP DECOUPLING & DEPENDENCY FIXES
   - Updated `backend/app/chatbot.py` to load the existing ChromaDB vector store instantly
     on startup rather than re-crawling/re-building database every launch.
   - Added `langchain-huggingface` to `requirements.txt` and `requirements-updated.txt`.
   - Fixed PyMuPDF deprecation warning (`import pymupdf as fitz`).
   - Fixed Windows console UTF-8 output encoding for special characters (₹, en-dash, bullets).
